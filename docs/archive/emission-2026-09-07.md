# Emission work archive — 7 September 2026

These reports record successive experiments and measurements, not a single
current implementation. See [compiler architecture](../compiler-architecture.md)
and [source structure](../source-structure.md) for current ownership and contracts.
Measurements use different baselines and must not be added together. Temporary
artifact paths below are historical evidence and may no longer exist.

The retained implementation separates semantic discovery from C++ naming, uses
structured header plans and projection caches, and passes explicit immutable
naming inputs and lookup-only semantic identities to rendering. Dependency
summaries are immutable; preparation and rendering remain serial.

The header worker pool (including `DOOF_HEADER_WORKERS`), frozen graph transfer
experiment, and duplicate instantiation catalogue were removed or rejected.
Their reports preserve the measured costs and constraints, not active plans.
Worker-model estimates are optimistic bounds, not measured parallel speedups.

The nominal-union guard and keyword lookup by identifier length were implemented
after their respective analyses. Earlier recommendations for these changes are
therefore complete. Other profiling candidates remain deferred hypotheses that
need fresh measurement before further work. Concurrency still requires an
appropriate checked-program and native-runtime ownership contract.

The final keyword report records 1,114 compiler tests and four supporting suites,
and six comparison pairs per project: median cold emission changed from 1,426 to
1,358 ms for Doof and 2,421 to 2,264 ms for Middai, with all 12 output comparisons
identical. These are recorded results; the documentation cleanup did not rerun
compiler verification.

## Cold emission phase timings — 2026-09-07

Before header-plan caching, Middai spends approximately 65% of cold command time in header planning. Actual C++ source rendering is only 3.4%. Parallel module emission could help, but the first optimization target is repeated header planning, including emission-context/instantiation-registry setup and projected declaration generation. These timings identify the phase, not the hot helper within it.

The subsequent [header-plan cache measurements](#header-planning-optimization) reduce cold Middai emission to 2.81 s.

<a id="cold-emission-timings-method"></a>

### Method

- macOS arm64; optimized development compiler built with `./install.sh`, installed into a temporary `DOOF_HOME`. Existing installed compiler was not replaced.
- Compiler base revision: `74f6913628010e5e95bfa742d77f91f03b143aec`, plus the phase-timing changes in this working tree.
- Middai base revision: `f821838565f6f4c3a6f08b2755badb0abf0ce271`, using its existing modified working tree. No Middai source was edited.
- Compiler SHA-256: `a5ca0311ff70337feaa34287f426d83277e4ca91000eb94fcc408cd30fd64bfa`.
- Bundled standard library; `DOOF_STDLIB_ROOT` unset. Bundle source digest: `0ad005caf1c9b79d2acc208a154d388d3534b54e55d1d8f9039ed5a2427735c8`.
- One initial run per project, followed by three serial cold runs per project, interleaved between projects. Every cold run uses a fresh temporary `-o` directory. OS file caches and acquired/prepared packages are not flushed.
- One warm run reuses the third output directory. Three further cold runs per project disable instrumentation. Benchmarks run after builds/tests finish.
- External wall time measures process invocation through exit; internal timings use the monotonic clock. Tables give medians per phase, so independently calculated medians need not add exactly. Parent phases include children.

<a id="cold-emission-timings-implications"></a>

### Implications

- Middai: header planning is 4.63 s of the 7.08 s internal command total. Inspect/memoize repeated projected-header work and immutable lookup construction first; profile inside that phase before selecting a specific cache key or refactor.
- Parallelizing only source rendering has a hard ceiling of about 0.24 s saved on Middai.
- Optimistically accelerating all module emission fourfold would reduce Middai to about 2.69 s; making it instantaneous would still leave about 1.22 s. These are Amdahl estimates, not implemented or measured parallel speedups; serial planning, scheduling, allocation, and memory-bandwidth costs will reduce the gain.
- Doof differs: checking plus decorated-type validation is about 1.09 s, exceeding its 0.96 s module emission. Its 0.46 s decorated-type validation deserves separate profiling; the equivalent Middai phase is only 0.035 s.

## Header planning optimization — 2026-09-07

Middai cold emission improves from **7.45 s to 2.81 s** (2.65× faster; 62% less wall time) by reusing identical projected header plans within a compilation. No parallelism or language semantics changed.

<a id="header-planning-optimization-finding-and-implementation"></a>

### Finding and implementation

The uncached detailed profile performed **41,509 section plans for 749 emitted modules**. Of approximately 4.49 s in header planning, declaration generation consumed 4.28 s, section-context setup 0.11 s and concrete declarations 0.024 s. Rebuilding declaration text was the principal opportunity; context/registry setup was secondary.

`emitter-header-cache.do` now retains pre-render plans within a single checked graph. It keys the exact ordered source-statement selection by defining module and source spans, plus the consumer’s concrete-interface selection. Graph-wide types, instantiations, naming and source mappings stay fixed for its lifetime. Every lookup returns private arrays: header compression mutates declarations and numbers synthesized aliases according to preceding sections. Cache templates cannot leak these renderer mutations to another consumer. The cache is discarded after graph emission.

Middai builds **2,457** plans and reuses **39,052**, a **94.1% hit rate**. Doof builds 465 for 927 requests. Doof has 119 emitted modules in this comparison because the compiler input now includes the cache module.

## Structured C++ header planning — 2026-09-07

The emitter now plans aliases from interned C++ type nodes and immutable declaration fragments. It continues to emit ordinary **`std::variant` and readable `using` aliases**. The generated C++ trees for Doof and Middai are byte-identical to those from the previous cached emitter on the same working trees, including existing header compression.

<a id="structured-header-planning-design"></a>

### Design

- One type-lowering path owns physical carrier decisions. A graph-local registry interns ordered template/type structure and qualified nominal identities; it does not sort variant arms or erase native template arguments.
- Immutable declarations contain text fragments and typed slots. Header alias selection counts eligible reference-only variant nodes before rendering. Comments, literals and already-lowered expression snippets remain opaque text. The old C++ template-string scanner and declaration string replacement are removed.
- Builders freeze into deeply immutable header plans. The exact-projection cache shares these plans directly, without copying declaration arrays. Source emission uses the same declaration/type lowering.
- Alias names remain local to a rendered header. Named aliases are preferred, reserved names are respected, alias-definition views avoid self references, and value-bearing variants are not hoisted across completeness boundaries.
- Canonical type spellings are cached per type ID and namespace. Alias-dependent memoization is local to a header alias view. Completed sections are cached by frozen-plan identity, namespace and incoming alias index; cache hits restore the outgoing index. All mutable caches are compilation-local and external to immutable plans.

The renderer still produces ergonomic C++; this change introduces no erased union representation, opaque runtime box or language-semantic change.

<a id="structured-header-planning-verification"></a>

### Verification

- **15 focused structured-IR tests passed.** They cover ordered variant identity, qualified nominal identity, native templates, immutable builder snapshots, preferred/synthetic aliases, value-bearing exclusions, preservation of comments/literals, separate canonical and alias-dependent rendering caches, and alias-state restoration on section-cache hits.
- **`./scripts/test.sh` passed all 1,064 compiler tests**, plus the supporting build-dispatch, runtime-scheduler, bootstrap-refresh-script and installer-layout checks.
- All `.cpp`, `.h` and `.hpp` files were byte-identical between before/after compilers for Doof and Middai in every one of three paired cold runs. Existing synthetic-alias output and header sizes were preserved on both workloads.
- The old text scanner could treat type-like comment/literal text as C++ syntax. The new tests require that such text remain untouched; pathological inputs relying on that erroneous rewriting intentionally differ.

## Repeated type lowering measurements — 2026-09-07

The measurements support caching before recursive C++ lowering. Interning currently avoids retaining duplicate nodes, but repeatedly traverses semantic types, allocates argument arrays, and builds lookup keys before finding existing nodes. This is particularly expensive for Doof self-emission. Generic substitution and the legacy fresh-registry helpers are much smaller costs in these workloads.

<a id="repeated-type-lowering-measurements-method"></a>

### Method

A disposable source copy at `/private/tmp/doof-lowering-probe` was instrumented and installed with `./install.sh`, using the previously verified structured-emitter compiler as the seed. Production source, installed compiler and generated bootstrap were not changed by this experiment.

The probe uses one process-local state object, enabled only for measurement. It counts contextual lowering calls, recursive semantic/C++ node visits, and shared/fresh-registry intern attempts and misses. It tracks distinct contextual result IDs separately for header and source phases. Timers surround generic substitution, registered-type reconstruction, C++ lowering, and legacy lowering/rendering. C++ lowering timings include recursive interning and counter overhead; they are not exclusive interning timings. Other class-inner helper paths contribute recursive counts but are not included in the timed contextual wrapper.

Three serial fresh-output runs per project and mode alternate forward/reverse mode order. Modes are original binary, probe disabled, counters only, and counters plus clocks. OS/package caches are warm, `DOOF_TIMINGS=1`, and the bundled stdlib is used. All runs compile the same original project sources, not the instrumented compiler sources. A focused probe test passed, checking disabled counters, aggregation, phase separation and distinct-result counting.

Every generated `.cpp`, `.h` and `.hpp` file was byte-identical across all four modes on both projects in all three comparisons. Counter results were identical across every enabled run.

<a id="repeated-type-lowering-measurements-recommended-next-experiment"></a>

### Recommended next experiment

Memoize contextual semantic-to-C++ lowering before recursion, with a cheap key that includes all representation-affecting context. `ResolvedType` has no explicit stable ID, and Doof's supported hash-map keys exclude object references. A recursive textual semantic key may replace one expensive traversal with another. Establish cheap identity and the point at which cached semantic inputs are stable before choosing the cache implementation.

Preserve generic substitution, concrete-instantiation context, and value/return/payload representation distinctions. Namespace and header-local alias selection remain rendering concerns. Do not reconstruct checker decisions or change `std::variant` output.

This is primarily a Doof self-emission opportunity. Middai's dependency views/fingerprints and materialization remain larger targets than its source type lowering. If cheap memoization requires broad semantic changes, measure cheaper interning keys or avoiding intermediate reconstruction as narrower alternatives.

## Type-lowering memoization — 2026-09-07

Contextual C++ type lowering now checks a compilation-local object-identity cache before substitution, intermediate semantic reconstruction, and recursive interning. The emitted C++ still uses the same `std::variant`, ordered alternatives and readable aliases.

<a id="type-lowering-memoization-implementation"></a>

### Implementation

- `semantic.do` adds an optional non-semantic identity stamp to resolved type objects. `semantic-type-identities.do` assigns IDs lazily within one emission graph, using owner tokens rather than a global counter. Structurally equal but separately allocated semantic objects retain distinct IDs.
- `emitter-type-cache.do` owns graph-level memoization for already-specialized C++ lowering and separate contextual sessions for each module/header context. Concrete mappings are configured before enabling the session and remain fixed for its lifetime.
- Contextual value and return caches are separate. Switching substitution identity clears all contextual stages; recursive registered-type reconstruction and ordinary C++ child lowering also memoize. Existing weak, class-inner and payload representation rules remain intact.
- Standalone emitter contexts default to uncached operation. The graph emission path enables caches only after checking and instantiation planning. Semantic child arrays, symbol properties and substitution argument arrays are read-only during this interval by the emitter ownership contract; their deep immutability is not enforced by a new language feature.
- Identity stamps retain only an owner token and integer, not the graph or cache. Re-emitting the same checked graph with a different identity owner is safe. This remains serial emission: lazy identity assignment and mutable tables are not yet suitable for shared concurrent access.

<a id="type-lowering-memoization-verification"></a>

### Verification

- **9 focused TypeLowering tests passed**, covering object/graph identity, semantic equality unaffected by stamps, cache opt-in, substitution invalidation, recursive child reuse, value/return/payload distinctions, concrete mapping isolation, missing-registration diagnostics, nominal/variant order, and repeated graph emission.
- **`./scripts/test.sh` passed all 1,072 compiler tests**, plus build dispatch, runtime scheduler, bootstrap refresh script and installer workflow checks.
- Every emitted `.cpp`, `.h` and `.hpp` file was byte-identical between old/new compilers on Doof and Middai in **all three paired comparisons**. Both compilers read the same final source trees.

## Dependency views and fingerprints investigation — 2026-09-07

This investigation used a disposable compiler copy. Production algorithms, the ordinary installed compiler and generated bootstrap were not changed. It identified a small fingerprint-construction improvement, a smaller native-header-closure improvement, and rejected a per-view type-ID visited set.

<a id="dependency-planning-investigation-measurement-method-and-limits"></a>

### Measurement method and limits

The baseline is the verified type-lowering-memoization compiler. The temporary compiler supports independent flags for a fingerprint StringBuilder, one native-header expansion per module/header per view, and a per-view semantic-type visited set. All experiments preserve the original dependency and hashing inputs. The type experiment shares the lowering graph's SemanticTypeIdentities domain, avoiding restamping between planning and lowering.

Experiments ran serially on both final Doof and Middai source trees, using fresh output directories, bundled stdlib and warm OS/package caches. Each timed mode ran three times with reversed mode order on alternating repetitions. Detailed clocks/counters have their own modes. Additional untimed audit modes collect ordered module/declaration-span/interface-key transcripts. Fingerprint digests are checked across modes of the same experimental binary. The original and experimental binaries also undergo byte-for-byte C++ tree comparisons.

The first probe mixed costly audit/size calculations into timing. Later probes guard the prefix-size calculations behind profiling and separate plan auditing from ordinary timing. Even disabled probes retain branches/calls and bookkeeping, so experimental control timings differ from the original compiler. Compare candidate phases against the control in the **same experimental binary**; do not interpret instrumented subphase timings as an uninstrumented cost or promised saving. Whole-command wall times were variable enough to avoid a headline end-to-end percentage.

<a id="dependency-planning-investigation-fingerprints-repeated-growing-string-construction"></a>

### Fingerprints: repeated growing-string construction

Middai has 749 emitted modules. The fingerprint pass performs:

- 1,047,512 dependency-closure visits, including revisits;
- 132,937 reachable module/source records across the roots;
- 561,001 module-list membership checks;
- 17,780,407 bytes of final hash input;
- 3,015,015,828 cumulative source-prefix length units while building that input.

The last figure is the sum of growing prefix lengths, **not an allocator measurement**. The existing left-to-right string append expression repeatedly reconstructs the growing prefix. This explains why constructing roughly 18 MB of final input can do much more work than its final size suggests.

A representative instrumented Middai split was approximately 85 ms for dependency closure, 221 ms for source-input construction, 70 ms for SHA-256, and 1 ms for the final suffix. Size counters themselves add work, so the controlled candidate comparison is stronger evidence than subtracting these components.

Replacing growing-string concatenation with the existing StringBuilder reduced the fingerprint phase from **344.0 to 192.7 ms** in the corrected controlled experiment. A separate later experiment measured **340.3 to 188.5 ms** with the builder plus native-header deduplication; the latter does not change fingerprinting. Fingerprint digests stayed identical. This is the clearest small implementation candidate: preserve source order, dependency closure, global instantiation/JSON input and initialization ordering exactly, while changing only construction of the input bytes.

Doof's fingerprint phase is already only about 5 ms in the original binary, so this is primarily a Middai opportunity.

<a id="dependency-planning-investigation-views-redundant-native-header-closure-is-real-but-secondary"></a>

### Views: redundant native-header closure is real but secondary

Middai attempted 9,552 native-header expansions for only 1,026 distinct `(defining module, native header)` pairs when counted separately per view. One expansion per pair reduced:

| Counter | Original traversal | One expansion |
| --- | ---: | ---: |
| Native-header expansions | 9,552 | 1,026 |
| Native sibling symbols scanned | 288,221 | 19,312 |
| Native exported symbols scanned | 286,686 | 19,232 |
| All symbol-collection visits | 966,191 | 715,588 |

The selected-symbol count stayed 117,562 and ordered plans matched. View planning improved by approximately **17–35 ms** across the controlled experiment rounds. This is a small cleanup, not the main remaining bottleneck. Production coverage would still need cycles, multiple native headers per module, nominal imports/re-exports, and interface-key order before landing it. A production key should use an unambiguous encoding of the pair.

<a id="dependency-planning-investigation-rejected-experiment-a-per-view-type-id-set"></a>

### Rejected experiment: a per-view type-ID set

Before deduplication, Middai made 2,462,475 recursive type visits. With a per-view type-ID visited set, it made 2,366,939 attempts and expanded 2,110,039 types: only 256,900 attempts (about 10.9%) hit that set. This is very different from the earlier high rate of equivalent C++ outputs; output equivalence did not imply object-identity reuse within a view.

In the final experimental binary:

| Middai mode | Fingerprinting | View planning |
| --- | ---: | ---: |
| Experimental control | 340.3 ms | 479.6 ms |
| Type-ID set only | 348.2 ms | 581.1 ms |
| Builder + native-header deduplication | 188.5 ms | 450.8 ms |
| All three experiments | 186.7 ms | 517.9 ms |

The type-ID set added identity/lookup work without avoiding enough traversal. Reject this form of memoization for view planning.

<a id="dependency-planning-investigation-larger-remaining-candidate-declaration-dependency-summaries-across-views"></a>

### Larger remaining candidate: declaration dependency summaries across views

Middai performs 123,713 statement-surface visits, 450,664 expression visits, and 2.46 million type visits. Ordering scans 567,983 candidate declarations to recover 114,719 selected statements in source order. Detailed profiling puts most view time in root/surface selection, with another roughly 100 ms in ordering; concrete-specialization seeding is only a few milliseconds.

The next design to investigate is a graph-local, immutable **direct dependency summary per foreign declaration**, built once and replayed by each consuming view. It would contain ordered symbol/interface-key dependency events derived from checked types, annotations and defaults. Projection would retain its per-view selected sets and follow symbol edges in the same order as today. Root-owned bodies remain a distinct policy: foreign declarations exclude bodies, while the root includes them.

This targets repeated traversal across consumers without caching a whole root-dependent transitive closure or changing checker decisions. Indexing original declaration positions could also reduce the source-order recovery work. Neither improvement has been implemented or assigned a claimed speedup here; ordering, opaque native closures, re-exports and concrete interface implementors are correctness constraints, not dispensable work.

## Dependency planning optimizations

The two small changes measured in `dependency-planning-investigation.md` are now
implemented in production Doof source. Module fingerprint input uses a
StringBuilder instead of repeatedly copying the accumulated string. Native
header closure expands once per defining-module/header pair per worldview,
marking the pair before traversing recursive dependencies.

Fingerprint bytes and invalidation inputs are unchanged. The native visitation
set belongs to the consumer's WorldviewIndex, so reusing a WorldviewGraphIndex
does not suppress dependencies in later consumers. No type-identity visitation
set was added: that prototype was slower.

### Path toward parallel emission

These changes reduce serial work; they do not make emission inputs immutable.
The next measured redesign is an immutable ordered direct-dependency summary
for each foreign declaration. Consumers could traverse those summaries using
private selection sets instead of repeatedly walking checked AST surfaces.
Root bodies still need their distinct dependency traversal, and replay must
preserve native closure, defaults, annotations, concrete interfaces and order.

Before workers share emission inputs, semantic identity assignment must happen
before dispatch or use independent storage. The C++ interner and lowering memo
tables must also be frozen or isolated. Selection sets, alias numbering and
rendering caches remain worker-local. Preserve ergonomic std::variant output
through that work.

<a id="immutable-dependency-summaries"></a>

## Immutable dependency summaries

`emitter-dependencies.do` now extracts ordered direct-dependency events from
checked declarations. The events contain scalar symbol identities and concrete
interface keys, with no AST, Symbol or ResolvedType references. Event fields,
event arrays and the graph's summary map are readonly.

Each named declaration's foreign surface is analyzed once during graph indexing.
Worldviews replay these summaries recursively with private selection, interface
key and native-header visitation sets. Root bodies are extracted separately;
foreign bodies remain excluded. Default expressions, aliases, enum values and
interface implementations retain their existing traversal rules. Immediate
recursive expansion preserves first-seen interface-key ordering, while emitted
declarations retain source order.

<a id="prepared-module-emission"></a>

## Prepared module emission

Subsequent work: [bounded header workers](#header-emission-workers). The
measurements and remaining-work discussion below describe this earlier stage.

The architectural target is serial preparation of shared immutable inputs,
followed by independent module rendering. This refactor establishes that phase
boundary without starting threads.

<a id="prepared-module-emission-ownership"></a>

### Ownership

- All worldview and header preparation completes before source rendering begins.
  Prepared headers contain readonly typed plans and immutable rendered text.
- CppTypeRegistry snapshots publish readonly node and canonical-render maps.
  Source renderers inherit those nodes and use private interning/render overlays.
  Inherited IDs remain stable; newly allocated IDs are local to each overlay.
  Never mix new nodes or ID-keyed caches from different overlays.
- Source renderers own their lowering/session and JSON-eligibility caches.
  Their results do not flow back into preparation caches.
- Pending jobs retain module metadata, visible module paths, the root program and
  prepared header. They do not retain configured emitters with copied graph
  lookup data. Each job is released as its output is produced.
- Results occupy their original graph positions, preserving mixed reuse and
  coverage order. Visible paths preserve namespace directives without retaining
  foreign projection ASTs in pending jobs.

The queue deliberately remains serial. Its program references still point into
the checked graph; SemanticTypeIdentities still writes emissionIdentity stamps,
and emitter-names.do still has process-global namespace mapping/cache state.
Independent identity owners do not make simultaneous writes safe. The next work
is an explicit read-only semantic identity and namespace-input contract before
adding a scheduler.

## Read-only identity and naming inputs

Subsequent work: [bounded header workers](#header-emission-workers). The
measurements and remaining-work discussion below describe this earlier stage.

Source rendering no longer writes semantic identity stamps or uses mutable
process-global namespace state. This completes the two shared-write changes
identified by the prepared-module refactor; it does not introduce a scheduler.

<a id="read-only-emission-inputs-naming-contract"></a>

### Naming contract

ModuleNames contains deeply readonly mapping records and precomputed namespace
strings. The compiler creates one snapshot after checking, before instantiation
planning. It is passed explicitly through generic-name mangling, header/source
contexts, C++ type lowering, imported namespaces, diagnostics, native headers,
patterns, JSON and Wasm support. Unknown paths are computed without cache writes.
Standalone helpers default to an empty mapping, never the last compilation's
configuration. Longest-prefix selection, prefix boundaries, sanitization and
output-root handling retain their previous behavior.

<a id="read-only-emission-inputs-identity-contract"></a>

### Identity contract

Dependency extraction and header planning assign IDs in serial preparation.
Semantic children are prepared once, including constraints, reflection wrappers,
root-body types and concrete generic arguments. SemanticTypeIdentitySnapshot
contains a readonly owner token and a lookup-only method; it cannot assign IDs.
Source renderers receive this snapshot in their private lowering state.

Unprepared, freshly reconstructed or differently owned types return -1. Value,
return, registered-type and lowered-C++ cache paths bypass that sentinel. Two
scratch types therefore cannot collide, and a miss never stamps a shared object.
This intentionally keeps existing contextual hits without assuming structural
equality or emitted C++ equivalence is semantic object identity.

The checked graph still contains mutable fields at the language type level.
Checking or another preparation pass must not overlap rendering of the same
objects. A worker scheduler still needs the remaining AST/native runtime
concurrency contract validated; removing these two writes alone is not proof
that every reachable operation is thread-safe.

## Header emission workers

**Historical experiment, removed 2026-09-07.** The opt-in actor pool and
`DOOF_HEADER_WORKERS` setting were removed during simplification. Serial header
planning, projection caches and rendering remain. The measurements below explain
why the worker machinery was not retained.


Header planning remains serial. The default CLI path renders each header during
preparation, preserving its existing shared cache and memory behavior. With
workers enabled, once preparation publishes `CppTypeSnapshot`,
`emitter-header-workers.do` can dispatch deeply immutable `HeaderSection` plans to
actors. Each actor owns its registry overlay and persistent header render cache.
No checked AST, mutable semantic graph, or shared memo table crosses the boundary.
Synthetic compound aliases and ergonomic `std::variant` output are preserved.

The pool keeps one outstanding task per actor and refills the actor whose result
completes first. Dense input indices restore deterministic output order. Workers
retire on completion or promise failure, draining accepted work. Invalid indices
are rejected before dispatch. Empty input starts no actors; one job or one worker
uses direct rendering. Worker exceptions are reported as internal render failures.

The batched path currently increases peak memory substantially on Middai; it is
an explicit experiment, not the production default.

`DOOF_HEADER_WORKERS=2`, `4`, or `8` selects the experimental pool for CLI emission.
The default is one. Counts clamp to 1–8; invalid strings fall back to one. This is
execution policy, so fingerprints do not include the worker count. Reused modules
are excluded from the dispatch queue; their output positions and coverage IDs
remain stable.

Source rendering remains serial. Its checked `Program` recursively contains
mutable decoration fields, which Doof correctly rejects at an actor boundary.
Lookup-only semantic identities and explicit immutable naming removed known
writes but did not change those types' transferability. The next source-worker
step is a deeply immutable source representation or a separately designed owned
transfer boundary, without weakening isolation checks.

<a id="frozen-emission-graph-experiment"></a>

## Rejected graph-copy worker experiment

The experiment moved dependency views, header planning, lowering, and source
emission into temporary worker domains by freezing the existing checked graph
into a second indexed representation, then reconstructing a private mutable graph
in each worker. It preserved node identity, recursive references, checker-selected
construction plans, generic instantiations, coverage IDs, and module/cache order.

It is not retained in production source. The codec, reconstruction, cycle-release
machinery, checker-node transfer stamps, module worker path, and generated tests
were backed out. The preceding read-only-input refactors and opt-in header workers
remain. The restored tree passed all 1,107 compiler tests and the four supporting
suites; the archived patch also passes `git apply --check`. No normally installed compiler or generated bootstrap was changed.

<a id="frozen-emission-graph-experiment-evidence"></a>

### Evidence

The first implementation used string node tags and separately indexed source-span
records. Middai's median command time increased from 2.575 s serial to 6.035 s with
two workers. Reconstruction and cleanup dominated.

Replacing tags with integers and transferring spans as immutable values improved
that implementation substantially, but did not make it worthwhile. Final compact
prototype medians, three alternating-order runs per mode:

| Project | Serial command | Two-worker command | Serial peak RSS | Two-worker peak RSS |
|---|---:|---:|---:|---:|
| Doof | 2.298 s | 3.022 s | 239.5 MiB | 684.3 MiB |
| Middai | 2.495 s | 3.146 s | 466.6 MiB | 983.3 MiB |

For Middai, snapshot creation alone took 186 ms. Reconstruction totalled 1,056 ms
across workers and explicit cycle cleanup totalled 412 ms. Those summed worker
costs are not wall time. Per-worker graph indexing and lost cross-partition cache
reuse added further costs. The whole-program copy approach also required over
8,000 lines of generated production codec code plus a generator and tests.

All 12 final generated-C++ comparisons matched byte-for-byte. Correctness was
promising; performance and complexity were not. The original prototype passed
1,253 full-suite tests plus supporting suites. The compact revision passed its
142 focused tests and real-project output parity checks before being rejected.

<a id="frozen-emission-graph-experiment-revised-direction"></a>

### Revised direction

The checker should finish by publishing one immutable `CheckedProgram`, using
mutable construction state internally. Stable IDs can represent cyclic type,
symbol, and declaration references. The result should contain final semantic
decisions and expose no mutable checker state. Emission should consume that
representation directly, without a second graph codec or per-worker reconstruction.

After shared instantiation ownership and generated naming decisions are fixed,
module workers should be independent. Each can read the same immutable whole
program and own its dependency view, lowering, caches, and output buffers.
References to another module's declarations do not require that module to have
been emitted first. A checked-program output contract should be designed before
resuming worker implementation.

## Semantic instantiation boundary and worker modelling

**Historical modelling experiment.** On 2026-09-07 the provisional immutable
catalogue and actor-transfer wrapper were removed. Semantic discovery/C++ naming
separation and timing/model tooling remain. Discovery now returns one set of
semantic records, with an ordered union referencing those records. The opt-in
header workers were also removed. The descriptions and measurements below record
the earlier experiment; [simplification results](#emission-simplification)
describe the current implementation.


<a id="instantiation-catalogue-modelling-decision-being-tested"></a>

### Decision being tested

Can independent module emission save enough end-to-end time to justify making the
checker result immutable? The rejected graph-copy worker implementation does not
answer this question: its transfer and reconstruction costs dominated the savings.
This experiment separates ownership and measures the opportunity without adding
another transfer format or production scheduler.

<a id="instantiation-catalogue-modelling-implementation"></a>

### Implementation

- `checked-instantiations.do` owns specialization discovery and the existing
  fixed-point traversal. It consumes checker-decorated AST types and bindings;
  it does not import emitter modules or choose C++ names.
- Its deeply immutable `InstantiationCatalog` is an ordered demand index containing
  semantic keys, source ownership, type keys, JSON demands, and overflow facts.
  An actor-boundary regression verifies that the catalogue is transferable.
- `CheckedInstantiations` also retains the existing mutable AST/type bindings and
  concrete-interface implementation bindings. Those are **not transferable**.
  This is a small first boundary, not a completed immutable `CheckedProgram`.
- `emitter-monomorphize.do` assigns C++ names in the original cross-kind discovery
  order. Generic interface implementations resolve through semantic specialization
  keys. Existing emitter callers retain `buildInstantiationPlan` as a wrapper.
- Wasm can add entry-point JSON demands before module emission, using the same
  semantic traversal. The initial catalogue snapshot excludes those later demands.
- Nonconvergence diagnostics contain semantic specialization keys instead of C++
  spellings. The 256-instance threshold and bounded dependency trace are unchanged.

The discovery/naming split adds 159 production lines compared with the preceding
implementation; almost all existing traversal is moved unchanged. There are no AST
copies, thaw operations, new node identifiers, or general-purpose IR framework.
The existing synthetic compound aliases and ergonomic `std::variant` output remain.

<a id="instantiation-catalogue-modelling-reproduce-the-model"></a>

### Reproduce the model

Use a fresh output directory and serial header rendering:

```sh
DOOF_TIMINGS=1 dist/doof emit /path/to/project -o /tmp/fresh-output > /tmp/emit.log 2>&1
python3 scripts/model-emission.py /tmp/emit.log
python3 scripts/model-emission.test.py
```

`compiler.instantiation-discovery` and `compiler.instantiation-naming` are children
of `compiler.instantiations`. Per-module `module.prepare:<path>` covers fingerprint,
worldview, and header preparation; `module.render:<path>` covers source-renderer
construction and rendering. `module.reuse:<path>` distinguishes incremental reuse.
The model rejects reused modules, missing timings, and inconsistent totals.

There are two candidate worker boundaries:

1. **Rendering:** the current source-rendering phase, leaving preparation serial.
2. **Preparation and rendering:** all measured module work, assuming a future
   immutable checked program permits independent module preparation.

For each boundary the script subtracts measured module work from `command.total`
to obtain the serial residual. It reports an ideal lower bound and a longest-job-
first scheduling estimate for 2, 4, and 8 workers. The longest module limits gains
even with unlimited workers. Nested aggregate phases are never summed again.

These are optimistic models, not measured parallel speedups. They preserve the
benefits of serial shared caches, ignore contention and transfer/publication costs,
and assume unchanged per-module work on a worker. Serial header workers are a
required input: parallel header batch time is not attributed to individual modules.
The reported overhead budget for a 10% end-to-end saving is the most useful gate:
a negative budget means the boundary cannot reach that target even for free.

interface implementation data; the immutable demand index alone does not solve
that. Preparation currently benefits from serial caches, so the full-module model
is deliberately optimistic and does not prove that those gains are achievable.

## Emission simplification (2026-09-07)

The retained architecture separates semantic specialization discovery from C++
naming, and keeps structured header plans, projection caches, explicit module
names, dependency summaries, and phase/per-module timings.

Removed:

- The provisional immutable catalogue, duplicate semantic keys/type-key arrays,
  builder-to-catalogue freeze step, and actor-transfer-only test.

  now returns one `CheckedInstantiations` object. Its ordered union references

preceding experiment). Historical worker/catalogue reports remain as evidence,
with their superseded status explicitly marked.

## Remaining decorated-type validation cost

**Follow-up:** the proposed guard was subsequently implemented and tested. See
[implementation and measurements](#union-nominal-guard). The investigation below

Analysis date: 2026-09-07. Production compiler source is unchanged by this
investigation. The starting compiler includes the comparison-order improvement
that reduced Doof validation from approximately 456 ms to 314 ms.

<a id="remaining-validation-analysis-findings"></a>

### Findings

Optimized native stack samples put 608 of 764 samples within Doof's validation
subtrees inside `unionMutabilityConflict` (approximately 80%, inclusive of callees).
Individual runs ranged from 74% to 83%. Middai recorded only 5 of 85 validation
samples there. These are sampled stack proportions, not precise function timings.

Disposable counters restricted to the final decorated-type validation pass show:

| Count | Doof compiler project | Middai |
| --- | ---: | ---: |
| `validateResolved` visits | 1,012,186 | 581,064 |
| Union checks | 36,261 | 16,109 |
| Distinct union objects | 8,072 | 4,099 |
| Union arm pairs examined | 8,438,462 | 53,295 |
| Pairs if each union object were checked once | 1,838,317 | 21,513 |
| Pairs with a non-generic nominal class on the left | 8,434,485 | 43,245 |

Successful validation visits every pair, so the width-derived pair counts equal
actual pair-loop iterations for these error-free projects. Distinct objects were
counted by their address during this single validation pass; no persistent or
cross-compilation identity scheme was introduced. Union objects are retained by
the checked input during the pass. A second instrumented run reproduced the visit,
object and pair counts exactly.

Doof's cost comes from its wide semantic and AST unions: `ResolvedType` has 23
arms, `Statement` 28, and `Expression` 31. Optional forms add an arm. A 31-arm union
requires 465 pairs each time. One `ResolvedType` union object was checked 619 times;
multiple other objects represent the same broad family of types.

The names here refer to **nominal compiler classes**. For example, an arm named
`ArrayResolvedType` in Doof's own `ResolvedType` alias is a class representing an
array type; it is not itself an `ArrayResolvedType` semantic value at the level
being checked. Its class fields do not make it a collection-mutability conflict.

<a id="remaining-validation-analysis-recommended-next-change"></a>

### Recommended next change

Hoist the left arm out of the inner pair loop and skip the inner loop when that
arm is a `ClassType` with no type arguments:

```doof
for i of 0..<union_.types.length {
  left := union_.types[i]
  case left {
    class_: ClassType -> { if class_.typeArgs.length == 0 { continue } }
    _ -> { }
  }
  for j of (i + 1)..<union_.types.length {
    right := union_.types[j]
    // Existing conflict comparison and diagnostic remain here.
  }
}
```

This specific fast path follows from `compareTypes`: class comparison uses module,
name, argument count, and argument comparisons. With zero arguments, ignoring
collection mutability cannot make a previously unequal class pair equal. A right
arm of another kind is also unequal in both modes. Therefore none of the skipped
pairs can produce a mutability-only conflict, including duplicate nominal arms.

Measured skipped work would be **99.95% of Doof's union pair iterations**, leaving
3,977 pairs, and 81.14% of Middai's, leaving 10,050 pairs. Those are iteration
reductions, **not measured speedups**. Middai spends little time in this routine,
so its end-to-end benefit is likely small. Sampling suggests useful room on Doof,
but fresh uninstrumented before/after runs must establish the actual gain.

Keep the change specific: generic nominal types, collections, promises, tuples,
and other compound types still need the existing checks. Do not skip recursive
member validation, cache diagnostics, or deduplicate diagnostic occurrences. Tests
should cover nominal duplicates/distinct classes, nominal fields containing
collections, generic type arguments with nested mutability, and preservation of
the first conflict and source spans in mixed unions.

<a id="remaining-validation-analysis-why-this-precedes-memoization"></a>

### Why this precedes memoization

Repeated visits exist: union-object memoization could remove about 78% of Doof's
pair work, but still leaves approximately 1.84 million pairs. The stateless nominal
class guard avoids more work and adds no identity ownership, cache lifetime,
invalidation, or diagnostic replay concerns. It also removes repeated left-arm
array access and variant/shared-pointer copying from the inner loop, which appear
in the native samples. Existing ergonomic `std::variant` output is unaffected.

Middai's remaining validation samples mostly involve traversal, strings, allocation
and copying. Its roughly 33 ms validation phase does not currently justify a more
complex lazy-diagnostic or memoization design.

### First choice: keyword lookup

`emitter-names.do:isCppKeyword` tests a chain of **91** string equalities. Every

Across three optimized symbol-bearing samples per project, this helper accounted
for 178/3,563 Doof and 361/5,664 Middai sampled main-thread emit-path observations:

keywords of that length. The largest length bucket has 18 keywords; most are much
smaller, and unsupported lengths can return immediately. The current bucket counts
are 2:3, 3:8, 4:11, 5:14, 6:18, 7:11, 8:15, 9:6, 10:1, 12:2, 13:1, 16:1.

This preserves the exact existing keyword list and C++ naming policy. It needs no
hash table, memoization, initialization, or identifier-state machinery. Tests should
cover all 91 keywords, ordinary names of matching lengths, empty/long names, and
the existing stdin/stdout/stderr treatment. This is the best next candidate to
implement and benchmark; no gain is claimed before that comparison.

<a id="current-emit-opportunities-second-choice-repeated-declaration-lookup"></a>

### Second choice: repeated declaration lookup

`checker-symbols.do:declarationFor` finds a module and linearly scans its statements,
calling `symbolName` until it finds a match. It accounted for 412/5,664 (~7%) of
Middai's sampled main-thread emit-path observations, inclusive of callees.

An index owned by the analysis/module result could avoid repeated scans. This is
more invasive than keyword grouping: it must preserve first-match behavior,
original imported names, export wrappers, and the lifecycle of synthesized or
changed declarations. Avoid a global cache or a broad symbol/AST redesign merely
for this lookup. Confirm call/rejection distributions and index lifecycle first.

<a id="current-emit-opportunities-smaller-cleanup-frontend-cache-work"></a>

### Smaller cleanup: frontend-cache work

On a successful cold emit, `driver.do` constructs frontend state once for the check
cache and again for the emission cache. `frontendStateForCompilation` searches all
source files for each resolution probe and hashes matching source text again.

Reusing state within the invocation, or indexing sources by logical path, could
remove duplicate work. The complete first diagnostics/cache phase is only about
7 ms on Doof and 16 ms on Middai, so this is a small opportunity, not an explanation
for the entire materialization cost. Reuse must account for any package-input
changes across preparation and preserve both cache files and their contracts.

<a id="current-emit-opportunities-larger-costs-that-are-not-yet-simple-fixes"></a>

### Larger costs that are not yet simple fixes

- `CppTypeRegistry.intern` and `atom` are prominent on Doof. They build structural
  string keys even on hits. Optimizing this requires measuring key/arity/hit
  distributions; a new type-ID/cache architecture is not justified by samples alone.
- `compareTypes` is still prominent during checking. Its presence alone does not
  justify another blanket fast path; assignability and generic comparisons do
  necessary semantic work.
- Middai materialization samples largely involve actual writes and native copies.
  Repeated directory probes may be removable, but the phase includes real output
  work. Preserve content-aware writes and native-build timestamps.
- Parser functions rank highly if all threads' CPU samples are pooled. Parsing is
  already parallel: those counts should not be mistaken for equivalent serial
  wall time. The measured analysis phases above are the relevant scale.

<a id="keyword-length-optimization"></a>

## Keyword lookup by identifier length

Implemented 2026-09-07 following [current timing analysis](#current-emit-opportunities).

`isCppKeyword` now dispatches on string length before comparing keyword spellings.
The exact 91-keyword set is preserved; the largest group contains 18 words. Names
with unsupported lengths return immediately. No hash table, cache, shared state,
or wider emitter changes are involved.

`cppIdentifier` still appends exactly one underscore to keywords, leaves already
suffixed names unchanged, and handles `stdin`, `stdout`, and `stderr` separately.
Namespace escaping and native-member exceptions retain their existing rules.

<a id="keyword-length-optimization-verification"></a>

### Verification

- Focused tests check all 91 original keywords, already-suffixed names, same-length
  non-keywords, ordinary/empty/long/Unicode names, and stream-name exceptions.
- Full `./scripts/test.sh`: 1,114 compiler tests and all four support suites passed,
  including native keyword namespace compilation and native-interop regressions.
- Development compiler built with `./install.sh` into
  `/private/tmp/doof-keyword-length-install`; release installation and bootstrap
  sources were not refreshed.

The benchmark baseline is `/private/tmp/doof-union-guard-install/bin/doof`.
Both compilers consume the same final project sources, using fresh output
